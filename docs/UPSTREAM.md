# Upstream seam

`opera-devtools-mcp` is a fork of
[ChromeDevTools/chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp).

This document is the registry of every intentional divergence from upstream.
`scripts/verify-upstream-seam.ts` enforces it: unregistered drift in an upstream-owned file fails CI.

- Current fork base: `ec014d1` (upstream, v1.7.0).
- Upstream remote: `git remote add upstream https://github.com/ChromeDevTools/chrome-devtools-mcp.git`

## Intake runbook

```bash
npm install                      # runs `prepare`, which registers the opera-ours merge driver
git fetch upstream --tags
git merge upstream/main          # conflicts only in files registered below
npm run gen                      # regenerate cli-options, tool-reference, metrics
npm run verify-upstream-seam     # fails if an unregistered upstream file drifted
npm test
```

Then update the fork base commit above.

`npm install` is required. The `merge=opera-ours` entries in `.gitattributes` have no effect until
`scripts/setup-intake.ts` registers the driver; git does not warn about an unregistered driver, it
falls back to a normal three-way merge. `npm run verify-upstream-seam` fails when the driver is
missing.

## Design rules

1. **New behaviour goes in `src/opera/**`.\*\* New files never conflict.
2. **Upstream files get references, not rewrites.** Swap a hardcoded literal for a `branding.ts`
   constant, or add a hook call. Never copy an upstream block in order to modify it.
3. **Never fork a file by copying it.** Edit the upstream file minimally in place and make the
   Opera-named path a re-export shim.
4. **Generated artifacts are never hand-merged.** They use the `merge=opera-ours` driver and are
   regenerated by `npm run gen`.
5. **`src/opera/tools/opera.ts` must export only tool definitions.** `createTools` in
   `src/tools/tools.ts` does `Object.values()` over the module, so any other export is treated as a
   tool and breaks the build. Helpers live elsewhere under `src/opera/`.

## Prior art for rule 2

The fork once reverted upstream's `ToolHandler` extraction
([ChromeDevTools/chrome-devtools-mcp#2032](https://github.com/ChromeDevTools/chrome-devtools-mcp/pull/2032))
by copying the invocation path into `src/index.ts` and editing it there. Three regressions shipped as
a result:

1. `--redactNetworkHeaders` was parsed and then ignored — the copy dropped
   `response.setRedactNetworkHeaders(...)`, so headers were always redacted.
2. Disabled-tool CLI guidance was lost, and the e2e assertions were weakened to match.
3. The `opera-devtools` CLI could not invoke any `opera_*` tool: the generator wrote
   `chrome-devtools-cli-options.ts` while the shipped CLI imported a stale hand-maintained
   `opera-devtools-cli-options.ts`.

## Deliberately NOT upstreamed

`sendLog` / MCP logging notifications and `signal` on `Request` are generic enough to
upstream but are kept local by decision. If upstream adds equivalents, delete ours
rather than keeping both. (The `WaitForHelper` dialog fix was upstreamed as of
the 1.7.0 intake — the fork's older local copy was deleted.)

## Measuring the seam

Intake cost is approximated per upstream-owned file under `src/` and `scripts/` as the lines we
changed multiplied by the number of upstream commits touching that file since the previous fork base.
Files we changed heavily that upstream also changes often dominate the sum.

```bash
git diff --name-only <fork-base> -- src scripts | while read f; do
  git cat-file -e "<fork-base>:$f" 2>/dev/null || continue   # upstream-owned only
  ours=$(git diff --numstat <fork-base> -- "$f" | awk '{print $1+$2}')
  churn=$(git log --oneline <previous-fork-base>..upstream/main -- "$f" | wc -l | tr -d ' ')
  echo "$f|$ours|$churn|$((ours*churn))"
done | sort -t'|' -k4 -rn
```

At the `dca3c04` base, after the modularization: **2828** across 20 files, down from **6828** across
17 before it. About a third of the remainder (`chrome-devtools-cli-options.ts`,
`tool_call_metrics.json`) is generated and resolves via `npm run gen`, leaving a hand-merge surface
of roughly 1800. Re-measure after each intake. A rising score means a divergence has grown that
belongs behind a seam in `src/opera/`.
